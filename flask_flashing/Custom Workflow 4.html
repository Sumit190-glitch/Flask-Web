Roboflow Workflows cannot take .obj or .stl files directly as the main input. Workflows are built around image and video frame inputs, plus optional parameters, while Roboflow dataset upload supports images, videos, PDFs, and annotations, not 3D mesh filesBlogDocs.

Best setup for your web app:

  1. User uploads .obj or .stl on your website.
  2. Your frontend or backend renders the 3D file into one or more PNG/JPG preview images, for example front, side, top, angled view.
  3. Your website sends those rendered image(s), plus any user question, to a Roboflow Workflow.
  4. The workflow uses Anthropic Claude Sonnet 4.5 (claude-sonnet-4-5) to analyze the rendered model.
  5. Your website displays the workflow response in the same UI.

So the workflow input should be “rendered image + optional text prompt,” not the raw .obj or .stl file. I recommend using Anthropic Claude Sonnet 4.5 (claude-sonnet-4-5) because it is the best fit here for visual reasoning over the rendered 3D model screenshot. Sound good?
